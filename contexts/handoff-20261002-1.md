# Handoff: Multi-Column Wide View for Desktop

**Date**: 2026-10-02  
**Status**: Designed, not yet implemented

---

## What

A new semi-persistent view mode called `wide` that renders the task list in N side-by-side columns instead of a single scrolling list. Default is 3 columns.

```
wide        # toggle: off → 3 cols, on → off
wide 4      # set specific column count
```

The mode is persistent across sessions (like context) via localStorage key `tasca_wide`.

---

## Why

Tasca's current list view is optimised for a phone screen — one long vertical column, sorted by urgency. On desktop this means a lot of scrolling to review everything. The user's main desktop use case is **GTD-style reviews**: "let me see all of it at once." The wide view is intentionally NOT for daily action (that's `day`/`next`) — it's for periodic review of the whole backlog.

The streams feature was removed this session because it added complexity without being used in practice. The wide view is the replacement quality-of-life improvement.

---

## How

### State (`src/js/state.js`)

Add two exports:
- `wideColumns` — integer, 0 = off, N = column count. Loaded from `localStorage.getItem("tasca_wide")` on module init.
- `setWideColumns(n)` — sets the value and persists it: `localStorage.setItem` when n > 0, `removeItem` when n = 0.

### Command (`src/js/commands-registry.js`)

Inline handler in the `commands` object, like `day`/`today`:
- No arg or `toggle` → if currently off set to 3, if on set to 0
- Numeric arg → parse and clamp to `[1, 6]`
- `off` or `0` → set to 0
- Calls `setWideColumns`, prints a one-line confirmation, calls `ctx.runListRefresh()`

### Rendering (`src/js/ui.js`)

Two new internal functions inside the module:

**`renderCompactTaskRow(t, index, allTasks, checklistSummary)`**  
Like the existing `renderTaskRow` but:
- No urgency `<td>` (drops the 40px rightmost column)
- `font-size: 0.9em` on the description cell for density
- Same metadata order: icon → description → checklist summary → URL → project → due → tags → annotations count
- Zip expansion rendered inline as a `<div>` below the description (not as a separate `<tr>` — separate rows break the column layout)
- Checklist parents get the summary `(done/total)` passed in; their members are NOT rendered as sub-rows in wide mode

**`renderWideColumns(container, tasks, allTasks, displayMapRef, checklistGroups, n)`**  
Called from `renderTable` when `wideColumns > 0 && !isTodayView` (today view is action-oriented with sections, not suited to columns):
1. Zero-tasks guard → same empty state as normal view
2. Build `displayMapRef.value` sequentially from `tasks` — checklist parents only (no member UUIDs), matching the `next`/`isNextView` behaviour
3. Compute `perCol = Math.ceil(tasks.length / n)`, slice tasks into `n` groups
4. Create a `display:flex; gap:16px; align-items:flex-start` wrapper div
5. For each column: a `flex:1; min-width:0` div with `border-left:1px solid var(--base02); padding-left:12px` on columns after the first
6. Each column renders a plain `<table>` (no header row, no `.table-wrapper` — saves vertical space) of compact rows
7. Footer: `"N tasks shown."` — no column count mention (visible from layout)

**Indicator**  
After context/project banners and before the wide content, append a dim line:
```
⊞ 3 col
```
Style: `color:var(--base01); font-size:0.75em; margin-bottom:6px; padding:2px 8px; border-left:2px solid var(--base02)`. A CSS class `.wide-banner` in `src/css/style.css`.

**Hook in `renderTable`**  
After the banners block (around line 388), before the `totalTasks === 0` check, import `wideColumns` from state and branch:

```
if (wideColumns > 0 && !isTodayView) {
  // append wide indicator
  renderWideColumns(container, tasks, allTasks, displayMapRef, checklistGroups, wideColumns)
  print(container, false)
  return
}
// ... existing single-column path continues unchanged
```

### Wiring (`src/js/logic.js`)

Add `"wide"` to `VALID_COMMANDS`.

### Help (`src/js/commands-misc.js`)

## Extra Context

### Codebase conventions
- Vanilla ES6 modules, no build step, no TypeScript
- No semicolons (ASI style)
- Module-level mutable state exposed as plain exports or `{ value }` reference wrappers — see `displayMapRef` pattern in `state.js`
- Persistence pattern: load from localStorage at module init time (top-level), save in setter function — same as `historyState` for command history
- Commands follow the `ctx` pattern: `{ args, targetId, print, dbOps, displayMapRef, runListRefresh, execute, markDirty }`

### Rendering patterns to follow
- `renderTable` already builds a `DocumentFragment` (`container`), appends children, then calls `print(container, false)` once at the end — wide mode must follow this same flow
- The `isNextView` flag in `renderTable` controls checklist expansion vs. summary — wide mode behaves like `isNextView: true` for checklists
- `setProjectMetadata(projects)` must be called early in `renderTable` (already is); `renderCompactTaskRow` can use `formatProject` since metadata is set at that point
- `zippedUuids` is imported from `state.js` in `ui.js` already — zip expansion works in compact rows too

### Context system (for reference)
The `context` / `day` / `today` commands call `handleContext` which calls `setContext` (in `context.js`) and stores in localStorage key `tasca_context`. Wide mode is simpler — it doesn't interact with filtering at all, it's purely a rendering switch. There is no need to touch `context.js`.

### Screen geometry
Desktop screen is ~1400px. Terminal output has `padding: 0 10px`. No max-width. Three columns at `flex:1` with 2×16px gaps → each column ≈ (1380 - 32) / 3 ≈ 449px. Compact rows drop the 40px urgency cell leaving ~449px for description — comfortable. Font is 14px Monoid (monospace).
